b 智能网关项目中内嵌了linux 系统的原因是可以提高数据处理的并行度    -对（多线程）    
c 智能网关项目中内嵌了linux 系统的原因是Linux系统是免费开源的 -错

### 3. 关于消息队列

```
a  生产环境下网关系统通过websocket与mqtt的broker通信  -错（一般使用mqtt协议，网页才用）   
b  智能网关项目中的消息队列模块封装了mqtt客户端简化了外部对mqtt的操作。-对
c  智能网关项目中的消息队列模块收发数据采用QoS 1级别 ，性能较好，但可能丢失数据。 -错（级别1 不会丢失数据但是可能会数据重复）
d  智能网关项目中的消息队列模块采用“拉模式”，主动的去获取mqtt的数据。-错（实际上是 被动的通过回调函数获得数据）
```

### 4. 关于多线程与多进程，以下描述正确的是：

```
a  开辟子线程与开辟子进程相比，线程占用资源更少，相同资源下可以并行执行的数量更多。 -对
b  多个子进程之间彼此隔离性更好，稳定性更高。 -对
c  进程之间的通信通常比线程之间的通信更加高效。-错 （线程间通信更方便更高效）
d  并行的线程越多性能提升越明显。 -错（cpu满负荷后 线程过多反而会拖累cpu）
```

### 5. 关于线程池模块以下描述正确的是：

```
a  线程池可以提高线程的利用率，避免反复开辟新线程。 -对
b  线程池通过mqueue可以让空闲的线程主动争取任务。  -对
c  当线程池中的线程都在忙时， 新任务到达时，线程池模块会报出错误。 -错（如果线程都忙，任务会暂存在队列中，只有队列满了 会报错）
d  线程池中的线程数量应该参考可能并行执行任务数。-对
e  锁的范围越大线程并行的能力就越弱。  -对（合理控制锁的范围）
```

### 6. 关于缓冲模块 以下描述正确的是：

```
a  缓冲模块的作用是作为不同工作线程的数据中转站。 -对
b  采用双缓冲模式的好处可以解决读写分离，两者不会互斥。  -对
c  项目中的写缓冲被写满时会触发读写缓冲区的交换。 -错（读缓冲区为空时）    
d  在某个线程触发读写交换时，其他的线程都不能再进行读写操作。 -对
e  整个项目中分为上行缓冲区和下行缓冲区两者之间的锁各自独立，没有互斥关系。-对
```

## 第二部分：问答题

### 1. 说说网关项目的功能和实现流程

```
- 功能
让多个不同设备A（不能联网），借助“智能网关”及其所在的本地设备B（能联网），实现与远程服务器和远程设备C（能联网）进行实时通信。
- 实现流程
	包含上行和下行两个过程
	上行：读取网关接收到下游设备发送过来的消息，处理后发送给远程MQTT服务器，进而发给远程客户端
	下行：接收到远程设备通过远程MQQT服务器发过来的消息，处理后通过蓝牙发给下游设备
- 上行的实现：
    注册接收到远程消息的回调函数： app_mqtt_registerCallback(receive_msg_callback), 在回调中
		将Json消息转换为字节数组消息：app_message_jsonToBytes()
		写入下行缓冲区：app_buffer_write(down_buffer)
		将后续的任务交给线程池执行：app_pool_registerTask(write_task_func)
	在write_task_func函数中
		从下行缓冲区读取一个字节数组消息：app_buffer_read(down_buffer) => bytes_data
		从字节数组消息取出device_id,并生成保持寄存器数据target_angle和max_speed
		将数据写给下游设备：app_modbus_writeHoldReg()
		将当前设备id保存到设备id列表中
- 下行的实现
	创建线程不断读取所有下游设备的状态数据： thread_create(read_thread_func),在线程池中
		遍历设备id列表中每个device_id, 读取其状态  read_deivce_data()
	在read_deivce_data中
		读取输入寄存器：app_modbus_readInputReg()   cur_angle/motor_status
		生成字节数组消息 =>bytes_data
		将字节数组消息写入上行缓冲区：app_buffer_write(up_buffer)
		将后续的任务交给线程池执行：app_pool_registerTask(send_task_func)
	在send_task_func中
		从上行缓冲区读取一个字节数组消息：app_buffer_read(up_buffer)
		将字节数组消息转换为json消息：app_message_bytesToJson()
		发送给远程: app_mqtt_send()
		检查下游设备状态，如果状态值是0，从设备id列表删除设备
```



### 2. 说说网关项目的在线升级如何实现

```
1. 根据版本号判断是否需要更新 
	请求获取远程固件相关信息：版本号和文件哈希值   json
	解析json, 得到远程的各级版本号和文件哈希值
	比较远程和本地的版本号，如果远程版本号不大于本地版本号，则无需更新
2. 如果需要更新下载远程固件
3. 对下载的固件做校验，来确认下载的文件没问题
	生成下载完成固件的哈希（使用MD5或SHA加密算法生成），与远程文件哈希比较
	如果不同，校验不通过，删除文件，更新失败
	如果相同，校验通过
4. 重启系统，安装新的程序文件（自启动配置）
```



### 3. 说说守护进程的功能和实现流程

```
- 功能
	1. 启动各个业务子进程（处理业务逻辑）
	2. 在业务进程意外结束后，自动启动业务进程执行（定时检查）
	3. 在守护进程结束前，关闭所有子进程
- 实现流程
	在守护进程程序启动时每隔一定时间检查所有业务子进程的状态
	1. 如果已启动，且正在运行中，不做任何处理
	2. 如果已启动过，但失败结束了，失败次数加1，如果失败次数超过了量大值，重新系统
	3. 无论是未启动过还是意外结束了，都创建一个新的进程去执行业务程序模块
	4. 休眠一定时间（比如2秒）
	注册一个进程被kill结束的信号监听回调中，一旦kill结束，去关闭所有子进程
```
